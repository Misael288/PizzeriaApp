# Adaptación visual al maquetado de Pizzería Planeta

Se armonizó la interfaz con la referencia —fondos claros, superficies blancas, azul marino, acentos coral, bordes suaves y tipografía sans serif— manteniendo intactos la lógica operativa, las rutas y contratos API existentes, las validaciones, los estados y los eventos. El dashboard ahora lee sus datos mediante un endpoint nuevo, de solo lectura y autorizado para ADMIN y CASHIER.

## Eliminación de productos

Solo el administrador puede eliminar un producto (cualquier tipo) desde **Catálogo** («Eliminar producto» en cada tarjeta) o **Inventario** (tarjetas de disponibilidad). El servidor lo exige con `DELETE /api/catalog/products/[id]` (mismo origen + rol ADMIN). Se borran en cascada receta, ingredientes y presentaciones; la imagen subida se elimina si ningún otro producto la usa. Para conservar el historial, `detalle_pedido.id_producto` pasó a ser opcional (`onDelete: SetNull`) y se añadió `nombre_producto` como copia del nombre; los pedidos antiguos se rellenaron y se muestran como «Producto eliminado» solo si no hubiera nombre guardado. Un pedido pendiente de confirmación que contenga un producto eliminado ya no puede confirmarse (mismo aviso de producto no disponible).

## Alcance y límites

La presentación incluye estados repetidos y métricas ilustrativas que no existen en los datos actuales. No se agregaron valores ficticios ni se modificaron contratos de APIs existentes para reproducirlos; las nuevas consultas del dashboard usan un endpoint separado de solo lectura. El día de Ventas hoy se calcula en la zona local del navegador y se convierte a límites UTC para la consulta; los cambios de estado y pago permanecen en Comandas. La cola de cocina se mantiene en su ruta actual, aunque el nombre de la ruta sea `/orders/history`.
